# Auto Light Lab — ห้องทดลองวงจรไฟรถยนต์

สื่อการสอนภาษาไทยสำหรับเรียนรู้อุปกรณ์และทดลองต่อวงจรไฟรถยนต์ ผ่าน 5 ภารกิจ พร้อมคำใบ้ ผลการทดลอง และประวัติในเครื่อง ออกแบบให้ใช้ได้ทั้งคอมพิวเตอร์ แท็บเล็ต และมือถือ ใช้ฟอนต์ Noto Sans Thai

โปรเจกต์เป็นเว็บไซต์ static ไม่ต้องติดตั้งฐานข้อมูล ไม่ต้องมีบัญชี Canva และไม่มีค่า API ใช้ JavaScript modules และไฟล์ภาพในโฟลเดอร์โปรเจกต์

## เปิดบนเครื่อง

1. ติดตั้ง Node.js เวอร์ชัน 18 ขึ้นไป (แนะนำรุ่น LTS ที่ยังได้รับการสนับสนุน)
2. เปิด Terminal ในโฟลเดอร์ `auto-light-lab`
3. พิมพ์ `npm start` แล้วเปิด [http://127.0.0.1:4173](http://127.0.0.1:4173)

บน Windows สามารถดับเบิลคลิก [START.bat](START.bat) แล้วเปิดที่อยู่ข้างต้นได้เช่นกัน ปิดเซิร์ฟเวอร์ด้วย `Ctrl+C` ในหน้าต่าง Terminal

ไม่ต้องรัน `npm install` เพราะเซิร์ฟเวอร์และการทดสอบใช้ความสามารถที่มีใน Node.js อยู่แล้ว ควรเปิดผ่าน HTTP ตามขั้นตอนนี้ การดับเบิลคลิก `index.html` โดยตรงอาจทำให้เบราว์เซอร์ไม่อนุญาต JavaScript modules

หากพอร์ต 4173 ถูกใช้อยู่ ให้ปิดเซิร์ฟเวอร์เดิม หรือใช้ PowerShell:

```powershell
$env:PORT = '4174'
npm start
```

จากนั้นเปิด `http://127.0.0.1:4174` เซิร์ฟเวอร์ตัวอย่างรับการเชื่อมต่อเฉพาะเครื่องนี้

## ใช้เป็นสื่อการสอน

| ภารกิจ | สิ่งที่ผู้เรียนฝึก |
| --- | --- |
| 1 — รู้จักอุปกรณ์ | จับคู่แบตเตอรี่ ฟิวส์ สวิตช์ รีเลย์ หลอดไฟ และกราวด์ |
| 2 — วงจรไฟหรี่ | ต่อแหล่งจ่าย ผ่านฟิวส์ สวิตช์ และหลอดไฟ กลับสู่กราวด์ |
| 3 — วงจรไฟหน้าพร้อมรีเลย์ | แยกวงจรควบคุมขดลวดรีเลย์ออกจากวงจรจ่ายไฟให้หลอด |
| 4 — ไฟสูงและไฟต่ำ | เข้าใจเส้นทางจ่ายไฟและการเลือกชุดหลอดไฟ |
| 5 — วิเคราะห์อาการเสีย | อ่านอาการและหลักฐานการตรวจ ก่อนเลือกสาเหตุ |

เลือกอุปกรณ์แล้วลากไปยังช่องจับคู่ หรือแตะอุปกรณ์และแตะช่องเป้าหมาย ต่อสายโดยเลือกขั้วต้นทางกับปลายทางตามคำแนะนำบนหน้าจอ ใช้คำใบ้ระหว่างเรียนและทดลองแก้ไขก่อนตรวจคำตอบ

แต่ละภารกิจเริ่มที่ **100 คะแนน** ตอบผิดหัก **10 คะแนน** ใช้คำใบ้หัก **5 คะแนน** คะแนนต่ำสุดคือ 0 เวลาใช้ประกอบการสะท้อนผลการเรียน ไม่มีโบนัสจากการทำเร็ว จึงไม่กดดันผู้เรียนที่ต้องใช้เวลาอ่านและทดลอง

แผนภาพในสื่อนี้เป็นแบบจำลองเพื่อเรียนรู้หลักการ ไม่ใช่คู่มือสายไฟสำหรับรถรุ่นใดโดยเฉพาะ ตัวอย่างรีเลย์แยกขั้วควบคุมและขั้วกำลัง เพื่อให้เห็นหน้าที่ของรีเลย์ได้ถูกต้อง

## ประวัติและข้อมูล

- ชื่อผู้เรียนและผลการเรียนเก็บใน `localStorage` ของเบราว์เซอร์ที่ใช้งานเท่านั้น ไม่มีการส่งไปเซิร์ฟเวอร์หรือฐานข้อมูล
- ประวัติจำกัด 500 รายการล่าสุด ตรวจรูปแบบข้อมูลและป้องกันบันทึก ID ซ้ำ
- อุปกรณ์อื่น เบราว์เซอร์อื่น หรือที่อยู่เว็บไซต์อื่นจะมีประวัติแยกกัน การล้างข้อมูลเว็บไซต์อาจทำให้ประวัติหาย
- หากเบราว์เซอร์ปิดกั้นพื้นที่เก็บข้อมูล ยังเล่นได้และเก็บผลชั่วคราวในหน่วยความจำ ผลนั้นจะหายเมื่อรีโหลดหรือปิดหน้า
- ประวัติในเครื่องเหมาะกับการฝึกและประเมินระหว่างเรียน ผู้ใช้เครื่องแก้ไขข้อมูลเองได้ จึงไม่ใช่ระบบสอบที่ป้องกันการแก้คะแนน

จุดเชื่อมต่อข้อมูลอยู่ที่ [src/storage.js](src/storage.js) สามารถเพิ่ม Supabase ในอนาคตผ่านชั้นข้อมูลนี้ โดยคงส่วนเกมไว้ได้ ยังไม่มี Supabase client, URL, API key หรือ schema ฐานข้อมูลในเวอร์ชันนี้

## เผยแพร่ด้วย GitHub Pages

1. สร้าง repository สำหรับเว็บไซต์นี้
2. อัปโหลด **ไฟล์และโฟลเดอร์ข้างใน `auto-light-lab`** ไปที่ระดับบนสุดของ repository ให้เห็น `index.html` ที่ root พร้อม `src/`, `assets/` และไฟล์อื่น ๆ อย่าอัปโหลดเพียงโฟลเดอร์ `auto-light-lab` ซ้อนอีกชั้น
3. ตรวจว่าไฟล์ `.nojekyll` อยู่ที่ root ด้วย เพื่อเผยแพร่เป็น static files
4. ที่ repository ไปที่ **Settings → Pages** เลือก **Deploy from a branch** แล้วเลือก branch **main** และโฟลเดอร์ **/(root)** จากนั้น Save
5. รอ GitHub แสดง URL ของเว็บไซต์ แล้วเปิดทดสอบทั้งมือถือและคอมพิวเตอร์

รูปแบบการตั้งค่า branch และโฟลเดอร์อ้างอิง [คู่มือ GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) หากใช้ชื่อ branch อื่น ให้เลือก branch ที่มีไฟล์เว็บไซต์จริง

ไฟล์เว็บไซต์อ้างอิง assets ด้วย relative paths เพื่อรองรับ URL แบบ `https://ชื่อผู้ใช้.github.io/ชื่อ-repository/` ไม่ต้องรัน Node.js บน GitHub Pages และไม่ต้องตั้งค่าฐานข้อมูล

## โครงสร้างและการแก้ไข

- [index.html](index.html) — จุดเริ่มต้นเว็บไซต์
- `src/` — ส่วนแสดงผล กติกาเกม การต่อวงจร และการเก็บข้อมูล
- `assets/` — ภาพประกอบและไฟล์สื่อ
- [src/storage.js](src/storage.js) — API เก็บชื่อและผลการเรียนในเครื่อง พร้อม fallback
- [scripts/serve.mjs](scripts/serve.mjs) — เซิร์ฟเวอร์สำหรับเปิดตัวอย่างบนเครื่อง
- [package.json](package.json) — คำสั่งเปิดเว็บไซต์และทดสอบ
- `tests/` — การทดสอบกติกาและข้อมูล

ทดสอบโค้ดด้วย:

```sh
npm test
```

ชุดทดสอบครอบคลุมผังวงจร การคิดคะแนน ข้อมูลประวัติที่ผิดรูปแบบ การบันทึกเมื่อเบราว์เซอร์ปิดกั้นพื้นที่เก็บข้อมูล และการอ่านผลที่เพิ่มจากอีกแท็บก่อนบันทึกผลใหม่

ดูรายละเอียดผลตรวจใน [QA-NOTES.md](QA-NOTES.md) และแนวทางจัดกิจกรรมเพื่อประกอบผลงานครูใน [TEACHER-GUIDE.md](TEACHER-GUIDE.md)

ฟอนต์ Noto Sans Thai เก็บไว้ใน `assets/` พร้อมใบอนุญาต [OFL](assets/OFL-NotoSansThai.txt) จาก [Google Fonts](https://github.com/google/fonts/tree/main/ofl/notosansthai) ภาพรถสร้างด้วยเครื่องมือ imagegen ดู prompt และไฟล์ต้นฉบับได้ใน [IMAGE-NOTES.md](assets/IMAGE-NOTES.md) จึงไม่ต้องเรียก CDN เพื่อแสดงฟอนต์หรือภาพ

เมื่อนำไปปรับใช้เป็นผลงานครู สามารถแก้ชื่อผู้จัดทำและชื่อสถานศึกษาในส่วนข้อความของหน้าเว็บ และเก็บภาพหน้าจอประกอบคำอธิบายกิจกรรมการเรียนรู้

## สิ่งที่แก้จากโค้ด Canva เดิม

- เปลี่ยนข้อความและภาพที่เดิมรอ Canva เติมให้ เป็นเนื้อหาและไฟล์ที่เว็บไซต์เปิดใช้ได้เอง
- ถอด Canva telemetry/data/editing SDK และการเรียกฐานข้อมูลของ Canva
- แก้การจับคู่ที่เรียกหา `<i>` หลังไลบรารีเปลี่ยนเป็น `<svg>` จนเกิดข้อผิดพลาด พร้อมรองรับการแตะและแป้นพิมพ์
- ปรับการต่อวงจรให้เห็นขั้วและหน้าที่ของอุปกรณ์ รวมถึงวงจรควบคุมและกำลังของรีเลย์
- ปรับเส้นเชื่อมและการจัดวางให้ทำงานเมื่อขนาดหน้าจอเปลี่ยน
- ปรับกติกาคะแนน ป้องกันรับคะแนนซ้ำจากการกดตรวจหลายครั้ง และแยกผลของแต่ละภารกิจ
- เปลี่ยนประวัติเป็นข้อมูลในเครื่อง พร้อมรองรับกรณีเบราว์เซอร์ไม่อนุญาต `localStorage`

ก่อนใช้สอนจริง ควรทดลองครบ 5 ภารกิจบนอุปกรณ์ของห้องเรียน และทบทวนถ้อยคำให้ตรงกับระดับของผู้เรียน
